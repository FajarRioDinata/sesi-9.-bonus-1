🔁 Soal 1 · Konflik Nama Antar Extension

⚠️ Dua extension dengan method nama sama (toInt) — return type berbeda
extension StringNumber on String {
    int toInt() {
        return int.parse(this);
    }
}

extension StringDouble on String {
    double toInt() {   // ← nama method sama, tapi return type berbeda
        return double.parse(this);
    }
}

void main() {
    String angka = '123';
    print(angka.toInt());
}

❓ Apa yang terjadi saat kode dijalankan?

⛔ Kode GAGAL dikompilasi (Compile-time error).
Compiler Dart akan melaporkan ambiguous extension reference atau conflicting extension methods karena terdapat dua extension dengan method toInt() yang sama-sama berlaku untuk tipe String. Pesan error khas: "The method 'toInt' is defined in multiple extensions: 'StringNumber' and 'StringDouble'. Try using the extension explicitly."

🔍 Penyebab Utama

  • Nama method identik & parameter identik (tanpa parameter): Dart melakukan resolusi method berdasarkan nama method + parameter types. Return type TIDAK termasuk dalam method signature untuk keperluan overload resolution antar extension.
  • Extension conflict scope: Kedua extension (StringNumber dan StringDouble) sama-sama berada dalam cakupan yang sama. Ketika menulis angka.toInt(), Dart tidak dapat memutuskan extension mana yang dimaksud karena keduanya memiliki tingkat prioritas yang sama (sama-sama “on String”).
  • Meskipun secara logis int dan double berbeda, tetapi secara teknis overloading berbasis return type tidak didukung di Dart, baik pada method biasa maupun extension.

🧩 Solusi Agar Kedua Extension Dapat Digunakan Tanpa Konflik

✅ 1. Memberi nama method yang berbeda (paling direkomendasikan)
Ubah nama method menjadi unik sesuai fungsionalitas. 
extension StringNumber on String {
    int toIntFromString() => int.parse(this);
}
extension StringDouble on String {
    double toDoubleFromString() => double.parse(this);
}
void main() {
    String angka = '123';
    print(angka.toIntFromString());    // 123 (int)
    print(angka.toDoubleFromString()); // 123.0
}
✅ 2. Panggil extension secara eksplisit (tanpa mengubah nama method)
Menggunakan sintaks ExtensionName(instance).method(). 
// extension masih memiliki method toInt() yang sama, tapi panggil secara eksplisit
void main() {
    String angka = '123';
    print(StringNumber(angka).toInt());   // memanggil versi int
    print(StringDouble(angka).toInt());   // memanggil versi double
}
Dengan pendekatan ini konflik terselesaikan karena programmer secara manual menentukan extension mana yang dipakai.
✅ 3. Satukan dalam satu extension dengan nama method berbeda (clean architecture) 
extension StringParsingExtension on String {
    int toIntSafe() => int.tryParse(this) ?? 0;
    double toDoubleSafe() => double.tryParse(this) ?? 0.0;
}

💡 Inti solusi: Hindari duplikasi nama method dengan signature sama (tanpa parameter) di extension berbeda yang berlaku pada tipe yang sama. Gunakan penamaan deskriptif atau panggilan eksplisit.

🔒 Soal 2 · Extension Method Tidak Bisa Mengakses Member Private

Private field (_value) tidak terlihat dari extension
class Counter {
    int _value = 0;    // private (library private)

    void increment() {
        _value++;
    }
}

extension CounterStats on Counter {
    int getValue() {
        return _value;    // ← baris bermasalah
    }
}

void main() {
    var c = Counter();
    c.increment();
    print(c.getValue());
}

❓ Mengapa kode di atas gagal dikompilasi?

❌ Error kompilasi: "The getter '_value' isn't defined for the class 'Counter'. Try correcting the name to the name of an existing getter, or define a getter or field named '_value'."
Penyebab: Member dengan awalan _ (underscore) di Dart bersifat library-private. Artinya, identifier tersebut hanya dapat diakses dari dalam library (.dart file) yang sama tempat ia dideklarasikan.
Extension CounterStats meskipun ditulis di file yang sama (atau bisa juga di file berbeda), tetap mengikuti aturan privat Dart. Karena _value dideklarasikan di dalam class Counter, namun akses dari luar library (atau dari extension yang merupakan top-level) tetap tidak diperbolehkan karena _value bukan anggota publik. Extension tidak memiliki hak istimewa untuk mematahkan enkapsulasi.

🔧 Perbaikan tanpa mengubah _value menjadi publik

✅ 1. Menambahkan method getter publik di dalam class Counter (tanpa mengubah field private)
Berikan method getValue() atau get value di dalam class yang mengembalikan nilai _value. Extension bisa memanggil method publik tersebut. 
class Counter {
    int _value = 0;

    void increment() { _value++; }
    
    // getter publik yang mengakses private field
    int get currentValue => _value;
}

extension CounterStats on Counter {
    int getValue() {
        return currentValue;   // ✅ akses via getter publik
    }
}

void main() {
    var c = Counter();
    c.increment();
    print(c.getValue());   // output: 1
}
✅ 2. Gunakan helper di dalam library yang sama (file yang sama) — memanfaatkan akses library-private
Extension yang didefinisikan di file yang sama dengan class Counter sebenarnya tetap TIDAK bisa langsung mengakses field _value karena aturan privasi Dart berbasis library, tetapi berbeda: jika extension masih dalam satu file yang sama, maka _value dapat diakses? Perlu diperjelas: field dengan underscore dapat diakses oleh kode lain dalam file yang SAMA (satu library). Jadi solusi termudah: tulis extension di file yang sama dengan Counter. Namun soal meminta “tanpa mengubah _value menjadi publik”, tetapi tidak melarang untuk memindahkan extension ke file yang sama. Contoh perbaikan: 
// === file: counter.dart (satu file) ===
class Counter {
    int _value = 0;
    void increment() { _value++; }
}

extension CounterStats on Counter {
    int getValue() {
        return _value;   // ✅ diperbolehkan karena masih dalam library/file yang sama
    }
}
// TETAPI: jika extension dipisah ke file lain, akses ditolak.
✔️ Namun skenario paling robust adalah tetap menggunakan getter publik agar extension dapat diakses dari mana pun tanpa ketergantungan satu file.
✅ 3. Menggunakan method (atau getter) internal namun diekspos melalui interface class (tanpa publik field)
Buat method int peekValue() di dalam class Counter yang mengembalikan _value. Extension tinggal memanggil method tersebut. 
class Counter {
    int _value = 0;
    void increment() { _value++; }
    int peek() => _value;    // method publik
}
extension CounterStats on Counter {
    int getValue() => peek(); 
}
🎯 Kesimpulan Soal 2: Extension method tidak dapat mengakses member private (_value) secara langsung karena Dart memberlakukan enkapsulasi berbasis library. Solusi yang paling idiomatis dan tetap menjaga privasi adalah menyediakan getter/method publik di dalam class asli yang mengembalikan nilai private, lalu extension memanggil getter tersebut. Dengan begitu akses tetap terkontrol dan privasi _value tidak bocor secara langsung.

📌 Ringkasan solusi cepat:
▪ Soal 1: Ganti nama method toInt() menjadi toIntSafe() dan toDoubleSafe() atau panggil extension eksplisit.
▪ Soal 2: Tambahkan getter publik di dalam Counter (misal: int get value => _value;) lalu gunakan getter tersebut di extension.

✔️ Kode perbaikan untuk kedua soal sudah mencerminkan best practice Dart & tetap menjaga enkapsulasi.
