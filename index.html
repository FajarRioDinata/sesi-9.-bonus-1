Konflik Nama Method di Extension Dart Extension clash

Analisis dampak & strategi resolusi konflik toString() pada dua extension berbeda

📌 Soal 1 · Konflik Nama Antar Extension

Perhatikan kode berikut:

extension StringNumber on String {
    int toString() {
        return toString(this);
    }
}

extension StringDouble on String {
    double toString() {   // ← method sama, return type berbeda
        return toString(this);
    }
}

void main() {
    String angka = '123';
    print(angka.toString());
}

Pertanyaan: Apa yang terjadi saat kode dijalankan? Jelaskan penyebabnya dan berikan solusi agar kedua extension dapat digunakan tanpa konflik.

⚠️ Apa yang Terjadi Saat Dijalankan?

❌ Kode GAGAL dikompilasi / error
Compiler Dart akan melaporkan ambiguous extension reference atau conflicting extension methods. Pesan error seperti:
"The method 'toString' is defined in multiple extensions: 'StringNumber' and 'StringDouble'. Try using the extension explicitly."

🔍 Penyebab Utama

  • Nama method identik — Kedua extension (StringNumber dan StringDouble) sama-sama mendefinisikan method toString() pada tipe String.
  • Signature method sama persis (dari sisi nama & parameter) — Meskipun memiliki return type berbeda (int vs double), Dart tidak menganggap return type sebagai bagian dari signature untuk overload resolution. Akibatnya compiler tidak bisa membedakan method hanya dari return type.
  • Ekstensi saling tumpang tindih — Saat memanggil angka.toString(), Dart tidak tahu extension mana yang dimaksud. Prioritas implicit extension tidak bisa menyelesaikan konflik karena kedua extension memiliki tingkat 'khusus' yang sama (sama-sama on String).
  • Masalah tambahan di dalam body method — Selain konflik, kode di dalam extension juga mengandung rekursi tak terbatas (return toString(this) tanpa this. akan memanggil dirinya sendiri, bahkan kalau tidak error konflik akan stack overflow). Namun yang utama error kompilasi lebih dulu.

Jadi intinya: konflik nama method toString() di dua extension yang sama-sama apply ke String menyebabkan kode tidak bisa dikompilasi.

🧩 Solusi Agar Kedua Extension Dapat Digunakan Tanpa Konflik

Ada beberapa pendekatan yang bisa dipakai, tergantung tujuan penggunaan. Berikut solusi paling efektif:

✅ 1. Gunakan Nama Method yang Berbeda (Rekomendasi utama)

extension StringNumber on String {
    int toIntFromString() {
        return int.parse(this);
    }
}

extension StringDouble on String {
    double toDoubleFromString() {
        return double.parse(this);
    }
}

void main() {
    String angka = '123';
    print(angka.toIntFromString());    // output: 123 (int)
    print(angka.toDoubleFromString()); // output: 123.0 (double)
}

Dengan memberi nama method berbeda (toIntFromString dan toDoubleFromString), konflik hilang dan kedua extension bisa hidup berdampingan.

✅ 2. Panggil Extension Secara Eksplisit (Tanpa mengubah nama method)

// extension tetap seperti semula (dengan perbaikan implementasi)
extension StringNumber on String {
    int toStringNumber() {   // ubah nama jadi tidak bentrok, tapi contoh tetap pakai explicit
        return int.parse(this);
    }
}
// TAPI kalau terpaksa ingin tetap pakai method toString (tidak disarankan),  
// panggil menggunakan syntax: ExtensionName(object).method()
void main() {
    String angka = '123';
    // tidak ambigu: panggil extension tertentu
    print(StringNumber(angka).toString());   // asumsi toString di StringNumber mengembalikan int
    print(StringDouble(angka).toString());   // memanggil versi double
}
💡 Dart memungkinkan pemanggilan eksplisit: ExtensionName(instance).method(). Meskipun method namanya sama, karena extension disebut secara eksplisit, tidak ada ambiguitas.

✅ 3. Gunakan Tipe Parameter Bantu Atau Method Berbeda Dalam Satu Extension (Refactoring)

Jika kedua fungsi tersebut bersifat utility yang erat kaitannya, lebih baik satukan dalam satu extension dengan nama method berbeda:

extension StringParsing on String {
    int asInt() => int.parse(this);
    double asDouble() => double.parse(this);
}

void main() {
    String angka = '123';
    print(angka.asInt());     // 123
    print(angka.asDouble());  // 123.0
}

✅ 4. Menghindari Override Method Fundamental (toString)

Method toString() adalah method bawaan dari Object. Mendefinisikan ulang toString di extension pada String sangat tidak disarankan karena dapat membingungkan dan konflik seperti ini. Lebih baik gunakan nama deskriptif lain.

Kesimpulan solusi paling clean: ubah nama method agar unik atau panggil extension secara eksplisit jika terpaksa method-nya harus bernama sama untuk keperluan desain tertentu (jarang). Pada kasus kode asli juga perlu diperbaiki implementasi yang rekursif dengan menggunakan int.parse / double.parse.

✨ Contoh Perbaikan Total (Recommended Final Code)

// Tidak ada konflik, nama method berbeda dan tidak bentrok dengan method bawaan
extension StringToNumber on String {
    int toIntSafe() => int.tryParse(this) ?? 0;
    double toDoubleSafe() => double.tryParse(this) ?? 0.0;
}

extension StringOps on String {
    // bisa juga extension lain tanpa konflik
    String get reversed => split('').reversed.join();
}

void main() {
    String angka = '123';
    print(angka.toIntSafe());      // 123 (int)
    print(angka.toDoubleSafe());   // 123.0 (double)
    print(angka.reversed);         // "321"
}

Pendekatan di atas menjawab akar masalah: menghilangkan ambiguitas method signature, sekaligus memperbaiki logika parsing yang benar dan aman.
